## 1. 文書目的

本書は、ラッコキーワードAPIを中核に、キーワード調査、検索需要分析、競合分析、コンテンツ制作支援、リライト優先度判定、検索順位監視、検索ソース別需要調査、AI SEOアシスタント、社内ダッシュボードを一体化した「SEOインテリジェンス基盤」の要件を定義する。EC/YouTube/画像企画と広告・LP判断の専用提案は推奨バックログとして扱う。

本書の目的は、開発者本人が自分用に実装する範囲、優先度、品質要件、制約、受入基準を判断できる状態にすることである。

## 2. 背景とゴール

### 2.1 背景

- SEO施策は、キーワード調査、競合調査、記事制作、順位監視、レポート作成が分断されやすく、属人化しやすい。

- ラッコキーワードAPIは、サジェスト、関連語、LSI/PAA、FAQ、検索ボリューム、競合サイト、獲得キーワード、見出し、共起語、順位チェックなど、SEO実務の主要データをAPI化している。

- これらのデータをDBに蓄積し、非同期ジョブ、スコアリング、AI生成、通知、レポートまで統合することで、継続的なSEO改善サイクルを実現する。

### 2.2 ゴール

| ゴール | 内容 | 評価指標 |
| --- | --- | --- |
| 調査時間の短縮 | 手作業のキーワード調査・競合調査を統合画面とジョブで自動化する。 | 1テーマあたり調査時間を70%以上削減 |
| 記事企画品質の向上 | 検索意図、上位見出し、共起語、FAQ、競合ページを基に構成書を生成する。 | 構成レビュー指摘数の削減、上位化率 |
| リライトROI向上 | 順位・流入価値・不足要素から改善対象を定量選定する。 | リライト後の順位改善率、推定流入増 |
| 競合監視の継続化 | 競合の獲得語・獲得ページ・流入価値を定期取得する。 | ギャップ検出数、対策完了数 |
| 運用品質の向上 | APIクレジット、エラー、ジョブ失敗、順位アラートを監視する。 | ジョブ成功率、APIエラー復旧時間 |

## 3. システム概要

本システムは、Webアプリケーション、アプリケーションAPI、非同期Worker、DB、Hangfireジョブキュー、Redisキャッシュ/分散ロック、外部APIクライアント、AI/通知/レポートコネクタで構成する。

```text
[利用者]
  -> [Blazor Web App / 管理UI]
  -> [ASP.NET Core API / BFF]
  -> [Application Services]
       -> [PostgreSQL: SEOデータ/ジョブ/レポート]
       -> [Hangfire/PostgreSQL: ジョブキュー/スケジューリング]
       -> [Redis: キャッシュ/分散ロック/レート制御]
       -> [Worker Service: Rakko API連携/集計/AI生成]
       -> [External Connectors: Rakko API, AI, Discord, GSC, GA4, CMS]
```

| 領域 | 実現内容 |
| --- | --- |
| キーワード探索 | サジェスト、関連語、LSI/PAA、FAQ、同時ランクインを統合し、候補語・検索意図・トピッククラスターを作成する。 |
| 検索需要・トレンド | 最大50,000語の一括調査を登録し、検索ボリューム、SEO難易度、CPC、広告競合性、月別推移、前年比を蓄積する。 |
| 競合分析 | 競合ドメイン、獲得キーワード、獲得ページ、競合ギャップ、集客価値、ページ価値を可視化する。 |
| コンテンツ制作 | 集客コンテンツ検索、見出し抽出、共起語、FAQから記事構成書、リライト指示書、AIプロンプトを生成する。 |
| 順位監視 | キーワード×URL/ドメインの順位チェックを非同期登録し、順位分布、推定流入、アラート、月次レポートを作成する。 |
| EC/動画/画像検索 | Amazon、楽天、YouTube、Google動画、Shopping、Imageのサジェストを使い、商品名、動画企画、画像SEOを支援する。 |
| 広告・事業判断 | CPC、広告競合性、検索需要、難易度からSEO/広告/LP/記事化の判断をスコアリングする。 |
| AI SEOアシスタント | 自然言語で調査、クラスタリング、構成案、競合差分、リライト指示、レポート生成を実行する。 |

## 5. スコープ

### 5.1 対象範囲

- キーワード候補収集、検索ボリューム・トレンド分析、検索意図分類、トピッククラスタリング。

- 競合サイト抽出、獲得キーワード/獲得ページ分析、競合ギャップ分析。

- 集客コンテンツ検索、SERP見出し抽出、共起語分析、記事ブリーフ生成、リライト指示生成。

- 検索順位チェック、順位履歴、順位分布、アラート、月次レポート。

- Google/Bing/YouTube/Amazon/楽天/Shopping/Imageなど検索エンジン別の候補語取得は、キーワード探索の検索ソースとして扱う。EC/YouTube/画像企画の専用画面・ワークフローは推奨バックログとする。

- CPC、広告競合性、検索需要、難易度は機会スコアへ反映する。広告/LP判断の専用提案は推奨バックログとし、CSV出力はMVP、Excel/PDF/共有URL出力とAIアシスタントはPhase 3で扱う。

- APIキー管理、クレジット消費監視、外部API障害時のリトライ/フォールバック。

### 5.2 対象外または拡張範囲

- Google Search Console/GA4/CMSへの直接連携は、初期版では拡張コネクタ扱いとし、設計上の差し込み口を用意する。

- 被リンク分析、技術SEOクローラー、本文全文解析は、外部サービスまたは別モジュールで追加する。

- ラッコキーワードAPIの利用規約に抵触する第三者提供・サービス組み込みは、法務/契約確認後に個別判断する。

- 複数利用者、テナント分離、RBAC、SSO、外部クライアント向けポータルは初期版では対象外とし、単一利用者で必要な監査・秘密情報保護に限定する。

## 6. 前提・制約

| 分類 | 前提・制約 |
| --- | --- |
| API仕様 | OpenAPI 3.1 / ラッコキーワードAPI v1.12.0を基準とする。 |
| 利用者 | 初期版の利用者は開発者本人1名とする。システム内では単一ワークスペース/単一管理者として扱い、操作主体は固定のdeveloperとして監査する。 |
| API認証 | 原則としてX-API-Keyヘッダーで認証する。地域/言語マスタの一部は認証不要。 |
| API利用 | ラッコキーワードAPIの契約プラン、APIキー数、データ利用範囲は契約確認日と確認者を記録し、変更時は要件・運用手順を更新する。初期想定はスタンダードプラン、APIキー最大5個、社内利用範囲とする。契約スコープは管理画面/APIでは管理しない。 |
| クレジット | レスポンスmeta.consumedCreditを保存し、全体/プロジェクト/APIキー/ジョブ単位で消費監視する。日次/月次予算、予算上限、承認制、予算超過による事前停止はアプリ内では管理しない。単一利用者前提のためユーザー別集計は行わない。 |
| レート制限 | 429時は指数バックオフ・再キュー。大量処理はキュー、同時実行数、外部API上限に基づく分割で制御する。 |
| 技術 | 新規開発は.NET 10 LTSを標準とし、ランタイム、SDK、CI/CD、コンテナベースイメージを.NET 10で統一する。 |
| データ鮮度 | 検索データは取得時点の外部API結果であり、実検索結果や各社仕様変更により変動する。 |

| --- | --- | --- | --- |
| FR-001 | プロジェクト管理 | プロジェクト、対象地域・言語、目標KPI、メモを登録・編集・アーカイブ（status=archived）・復元・参照できる。 | MVP必須 |
| FR-002 | サイト管理 | プロジェクト配下のsitesについて、対象サイト、競合候補、ドメイン、正規URL、種別、メモを登録・編集・アーカイブ（status=archived）・復元・参照できる。 | MVP必須 |

## 10. データ要件

データは、外部APIのローデータ、正規化キーワード、最新指標、時系列、分析成果物、ジョブ、監査ログに分けて保持する。ローデータは再解析・監査のため保存しつつ、UI高速化のため正規化テーブルと集計テーブルを併用する。テーブル、型、制約、インデックス、保持方針の詳細は`docs/db_design.md`を正本とする。

| ID | データ要件 | 内容 |
| --- | --- | --- |
| DR-001 | キーワード正規化 | 表記ゆれ、前後空白、Unicode正規化、言語、地域を考慮し、同一語をkeyword_idに集約する。 |
| DR-002 | メトリクス履歴 | 検索ボリューム、SEO難易度、CPC、競合性、firstSeenRangeは取得日時と地域/言語を保持する。 |
| DR-003 | 月別推移 | monthlySearchVolumeをyear_month単位で保存し、季節性・前年比を再計算できる。 |
| DR-004 | 外部APIローデータ | 各APIリクエスト/レスポンスは圧縮JSONまたはBlobに保存し、DBにはハッシュ、参照URI、保持期限、契約スコープを保持する。 |
| DR-005 | ジョブ履歴 | 外部requestId、内部jobId、分割実行単位、ステータス、エラー、リトライ回数、消費クレジットを保持する。 |
| DR-006 | 成果物 | 記事ブリーフ、レポート、AI生成結果はバージョン管理し、編集履歴、作成/編集者、レビュー状態、参照データを持つ。 |
| DR-007 | グローバルマスタ/分析結果の境界 | keywords等の正規化マスタはグローバル共有とし、取得条件・ジョブ・分析結果・成果物はワークスペース/プロジェクトスコープで保持する。 |
| DR-008 | 通知設定/送信履歴 | Discord Webhook通知先、通知種別、送信元ジョブ/リソース、送信結果、エラー、再送状態をワークスペース/プロジェクトスコープで保持する。 |
| DR-009 | API契約スコープ履歴 | ラッコキーワードAPIの契約プラン、APIキー数、データ利用範囲、確認日、確認者、適用期間、scope_keyを保持し、キャッシュ再利用と監査の判断根拠にする。 |

グローバル共有する検索指標キャッシュは内部最適化に限定し、画面/APIでは必ずワークスペース/プロジェクトスコープの取得条件・成果物として返す。キャッシュ再利用可否はラッコキーワードAPIの契約範囲とデータ利用範囲に従い、外部API実行時は実行元ワークスペース/APIキー/契約スコープ/消費クレジットを追跡する。契約スコープが異なるデータは共有キャッシュとして再利用しない。

## 12. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-001 | 可用性 | 管理画面・APIは月間稼働率99.5%以上を目標とする。外部API障害時も既存データ閲覧は継続する。 |
| NFR-002 | 性能 | 通常検索画面はP95 2.5秒以内。重いAPI連携は非同期ジョブ化し、画面はジョブIDと進捗を返す。 |
| NFR-003 | スケーラビリティ | APIサーバ、Worker、キュー、DBを水平/垂直拡張可能にする。大量調査は分割・キュー制御する。 |
| NFR-004 | 信頼性 | 外部APIは429/5xxを指数バックオフで再試行し、402/403/400は再試行しない。ジョブは冪等化する。 |
| NFR-005 | セキュリティ | APIキー・AIキー・OAuthトークンはKey Vault等のSecret Storeに保存し、DBには`key_ref`、`auth_ref`などの参照キーのみ保存する。 |
| NFR-006 | 認可 | 初期版は単一利用者前提のためRBACは実装しない。外部公開時に備え、操作主体、プロジェクトスコープ、監査ログは保持する。 |
| NFR-007 | 保守性 | Clean Architecture、外部APIクライアント抽象化、OpenAPI由来DTO、ユースケース単位のサービス分割を採用する。 |
| NFR-008 | 監視 | 構造化ログ、分散トレース、メトリクス、ジョブ監視、API消費クレジット、失敗率を可視化する。 |
| NFR-009 | データ保持 | ローデータ、加工データ、レポート、監査ログの保持期間をワークスペース設定で制御する。初期値はローデータ24か月、加工データ24か月、レポート36か月、監査ログ36か月とする。 |
| NFR-010 | 法務/規約 | ラッコキーワードAPIの利用規約・ガイドラインに従い、データの社外提供・組み込み用途は契約確認を必須とする。 |
| NFR-011 | バックアップ | DBは日次フル、WAL/ポイントインタイム復元を有効化。レポート・CSVはオブジェクトストレージに冗長保存する。 |
| NFR-012 | 国際化 | 日本語UIを初期実装し、DB・APIは多言語キーワードと地域/言語マスタに対応する。 |
| NFR-013 | 設計追跡性 | 要件、基本設計、API設計、DB設計の責務を分け、APIエンドポイント、DBテーブル、受入基準が主要機能要件へ追跡できる状態を維持する。 |

## 13. セキュリティ・権限要件

| 項目 | 要件 |
| --- | --- |
| 認証 | 初期版は開発者本人のみが利用する前提とし、ローカル実行時はOS/開発環境の保護に委ねる。本番相当環境へ公開する場合のみ単一管理者ログインを必須にする。 |
| 認可 | 初期版は全操作を単一管理者権限として扱う。ロール定義、ユーザー招待、外部クライアント権限はPhase 4以降の拡張対象とする。 |
| APIキー管理 | キー値はKey Vault等で保管し、DBにはkey_refのみ保存。閲覧は不可、ローテーション可能。 |
| データ分離 | 業務テーブルはworkspace_idまたはproject_idを持たせる。初期版は単一ワークスペースだが、将来の複数ワークスペース化に備えてスコープを明示する。 |
| 削除方針 | 業務データは原則として物理削除せず、プロジェクト/サイトはstatus=archived、API認証情報/通知設定はstatus=disabledで無効化する。必要に応じてstatus=activeへ復元/再有効化できる。 |
| 状態定義 | 管理対象の状態値は、active / archived / disabled を基本とする。通知送信履歴は pending / retrying / succeeded / failed を用いる。 |
| 監査ログ | APIキー操作、外部連携実行、CSV/レポート出力、AI実行、ジョブ操作を固定の操作主体developerで記録する。 |
| 個人情報 | 初期版ではユーザー情報・OAuthトークンを扱わない。将来コネクタでOAuthを使う場合は暗号化/最小化する。 |
| AI安全 | 外部に送るプロンプトからAPIキー・個人情報・秘密情報を除去。AI出力は人間レビュー前提。 |

## 14. 運用要件

| 項目 | 要件 |
| --- | --- |
| ジョブ監視 | ジョブ失敗率、滞留数、平均処理時間、リトライ回数、外部API別エラー率を監視する。 |
| クレジット監視 | 全体/プロジェクト/APIキー/ジョブ別の消費量、日次/月次集計、402発生を可視化する。単位はラッコキーワードAPIのconsumedCreditとし、日次集計はAsia/Tokyoの0:00、月次集計はAsia/Tokyoの毎月1日0:00で区切る。 |
| 障害対応 | 429は自動再試行、5xx/503はリトライ後にDiscord通知、403/402は開発者対応に切り分ける。 |

| データ保持 | 初期値はローデータ24か月、加工データ24か月、監査ログ36か月、レポート36か月。ワークスペース設定で延長/短縮可能。 |
| メンテナンス | API仕様変更時はOpenAPI差分検知、クライアントDTO再生成、契約テストを実行する。 |

## 付録A. ラッコキーワードAPI利用一覧

本システムで使用するラッコキーワードAPIのエンドポイントと用途を以下に示す。

| Method | Path | Summary | Request DTO | 本システムでの用途 |
| --- | --- | --- | --- | --- |
| POST | /v1/suggest-keywords | サジェストキーワード取得 | SuggestKeywordsDto | サジェスト収集、検索ソース別候補語取得、候補語拡張（EC/YouTube/画像企画は推奨バックログ） |
| POST | /v1/related-keywords | 関連キーワード取得 | RelatedKeywordsDto | 関連語辞書、ロングテール探索、除外語候補 |
| POST | /v1/other-keywords | 潜在的な検索キーワード/質問（LSI/PAA）取得 | OtherKeywordsDto | LSI/PAA、検索意図、FAQ/見出し候補 |
| POST | /v1/question-search | よくある質問検索取得 | SearchQuestionDto | FAQ抽出、FAQPage候補、顧客疑問DB |
| POST | /v1/ranking-keywords | 同時ランクインキーワード取得 | RankingKeywordsDto | 同時ランクイン、クラスタリング、1記事で狙う語の推定 |
| POST | /v1/search-volume | 一括キーワード調査登録 | SearchVolumeHistoryDto | 最大50,000語の一括需要調査登録 |
| GET | /v1/search-volume/{requestId}/status | 一括キーワード調査ステータス取得 | - | 一括調査ジョブの完了監視 |
| POST | /v1/search-volume/{requestId}/results | 一括キーワード調査データ取得 | SearchVolumeResultsDto | 検索ボリューム、SEO難易度、CPC、トレンド取得 |
| GET | /v1/metadata/locations | 地域一覧取得（クレジット消費なし・認証不要） | - | 地域マスタ同期 |
| GET | /v1/metadata/languages | 言語一覧取得（クレジット消費なし・認証不要） | - | 言語マスタ同期 |
| POST | /v1/influx-keywords | 獲得キーワード調査取得 | InfluxKeywordsKeywordDto | 自社/競合の獲得キーワード、ギャップ分析 |

| POST | /v1/co-occurrence | 共起語取得 | CoOccurrenceDto | 共起語、語彙網羅率、リライト差分 |
| POST | /v1/search-rank | 検索順位チェック登録 | SearchRankHistoryDto | 順位チェック登録 |

| POST | /v1/search-rank/{requestId}/results | 検索順位チェック結果データ取得 | SearchRankResultsDto | 順位結果、順位分布、推定流入、アラート基礎データ |
