# ゲストログイン手動テストチェックリスト

ゲストログインと分離Mockデモを、実ブラウザ・実環境で人が確認するためのチェックリスト。仕様の正本は`docs/guest_login.md`、画面仕様は`docs/screen_design.md`、エラー形式は`docs/api_design.md`とする。2026-09-28時点の実装（#156の結果の再表示・プロジェクト復元・候補語CSVの探索限定と、#157の初期データ・案内を含む）に基づく。仕様や画面の文言を変えたときは本書も更新する。

CIで実行される自動テスト（`WebGuestLoginTests`、`GuestDemoSessionTests`ほか。範囲は`docs/test_plan.md`の12章）は、主にサーバー側の判定とデモのデータを検証する。Chromiumで操作する`BrowserGuestLoginTests`は`E2E_GUEST_BROWSER_ENABLED`を設定したときだけ動き、CIでは実行されない。本書は自動テストで確かめていない観点を中心にする。具体的には、実ブラウザでの見え方と使い勝手、実機、公開環境の設定（HTTPS・Cookie・プロキシ・レート制限）、Excelで開いたCSVの確認である。

## 使い方

- 時間がない場合は「1. スモーク」だけを行う。リリース前と、認証・Cookie・ゲストデモに関わる変更の後は全項目を行う。
- 結果は項目ごとにOK/NG/未実施（理由）で記録し、日付付きのQA記録（例: `docs/qa/guest-browser-YYYY-MM-DD.md`）に残す。書式は末尾のテンプレートを使う。
- 項目の印:
  - 〔自動〕項目に書いた期待結果のすべてを、CIで実行される自動テスト（画面を通さない検証を含む）が確認している。時間がなければ後回しにしてよい。一部だけが自動化されている観点は項目を分け、自動化済みの側にだけ付ける。`BrowserGuestLoginTests`はCIで実行されないため、印の根拠にしていない。
  - 〔管理者〕管理者アカウントが必要。
  - 〔公開〕HTTPS・リバースプロキシ配下の公開環境でのみ確認できる。
  - 〔記録〕期待動作が仕様で決まっていない。挙動を記録し、問題があればIssue化を判断する。
- ブラウザは拡張機能を無効にしたプロファイルを使う。広告ブロッカー等がダウンロードを`net::ERR_BLOCKED_BY_CLIENT`で止めることがある（2026-09-23のQAで発生）。
- テスト中のゲストもログインから1時間で失効する。長いテストの途中で期限切れの案内が出たら時刻を記録して再ログインする（EXP-01の確認になる）。
- 同じブラウザで管理者としてログインするとゲストのセッションは失効する。管理者での確認は別のコンテキストで行う。
- 1つのゲストセッションで使えるのは、プロジェクト10件・サイト30件（どちらも初期データを含む）、自分で行う探索・調査・CSV出力の合計50回（初期データの6ジョブは数えない）までである。上限に達すると以降の作成・実行が拒否されるため、上限の確認は「11. 上限」で最後に、または別のコンテキストで行う。ほかの項目の途中で上限に達したら、再ログインして必要なデータを作り直す。

## 0. 事前準備

- [ ] 対象の環境URLとビルド（コミットID）を記録した。ローカルの既定は`http://localhost:5295`（HTTPSは`https://localhost:7026`）。
- [ ] 独立したブラウザコンテキストを2つ用意した（通常ウィンドウとシークレットウィンドウ、または別ブラウザ）。
- [ ] 期限切れの確認用に、3つ目のコンテキストでゲストログインしてログイン時刻を控え、画面を開いたまま1時間放置する（8章のEXP-02・EXP-03で使う）。
- [ ] 〔管理者〕管理者でログインし、通常データに見分けやすい名前のプロジェクト（例: `QA-通常データ`）があることを確認した。
- [ ] 〔管理者〕通常環境の`RakkoKeyword:Mode`（Mock/Real）を確認した。あわせて「設定・アカウント」のAPI使用量（日・月）と、管理画面の外部API呼び出し・ジョブ・監査ログの最新件数を控えた（7章のISO-04で比較する）。
- [ ] テストデータを用意した。PowerShellでクリップボードにコピーして貼り付けられる。

```powershell
1..100 | ForEach-Object { 'QA{0:D3}' -f $_ } | Set-Clipboard  # 検索ボリューム100件（上限ちょうど）
1..101 | ForEach-Object { 'QA{0:D3}' -f $_ } | Set-Clipboard  # 101件（上限超過）
'あ' * 100 | Set-Clipboard                                   # 100文字（名前・シード・キーワードの上限ちょうど）
'あ' * 101 | Set-Clipboard                                   # 101文字
'{"k":"' + ('a' * 3992) + '"}' | Set-Clipboard               # 4,000文字のKPI JSON（3993にすると4,001文字）
'=1+1', '"+SUM(1,2)"', '-10', '@cmd' | Set-Clipboard          # 数式対策の確認に使う4語（CSV-08）
```

検索ボリュームの貼り付け欄はCSVとして読まれ、カンマで語が分かれる。そのため、カンマを含む`+SUM(1,2)`はダブルクォートで囲んで`"+SUM(1,2)"`と入力する。囲まないと`+SUM(1`と`2)`の2語になる。

## 4. 操作できる機能

### プロジェクト

- [ ] PJ-01 名前・既定の地域・言語・メモ・KPI（JSON）を入れて作成すると、一覧とヘッダーのプロジェクト選択に反映される。
- [ ] PJ-02 名前が空だとブラウザの必須チェックで送信されない。空白だけの名前は「プロジェクト名・地域・言語を入力してください。…」で拒否される。
- [ ] PJ-03 同じ名前で作成すると「同名のプロジェクトが存在します。」で拒否される。
- [ ] PJ-04 KPIに`{invalid}`を入れると「JSONの形式を確認してください。…」が表示される。
- [ ] PJ-05 名前は100文字なら保存でき、101文字は拒否される。メモ1,000文字とKPI 4,000文字の境界も同様である（低優先）。プロジェクトの件数を増やさないよう、既存のプロジェクトを編集して確かめる。
- [ ] PJ-06 名前を編集すると一覧とヘッダーに反映され、再読み込み後も残る。
- [ ] PJ-07 アーカイブすると一覧から消え、状態フィルターを`archived`にすると表示される。復元すると元に戻る。
- [ ] PJ-08 〔記録〕選択中のプロジェクトをアーカイブしたときの、ヘッダーのプロジェクト選択と各画面の表示。
- [ ] PJ-09 ヘッダーでプロジェクトを切り替えると、サイト・ダッシュボード・ジョブ・探索結果が切り替わり、別プロジェクトのデータが混ざらない。
- [ ] PJ-10 名前に`<img src=x onerror=alert(1)>`を入れても文字列として表示され、ダイアログは出ない。
- [ ] PJ-11 プロジェクトを作成すると、そのプロジェクトがヘッダーで選択中になる。再読み込みしても選択が保たれる。

## 11. 上限（専用のセッション）

上限に達すると、そのセッションでは以降の作成・実行が拒否される。ほかの項目がすべて終わってから行うか、上限確認だけに使う別のコンテキストでゲストログインして行う。終わったらログアウトする（デモのデータは初期化される）。

- [ ] LIM-01 初期のデモプロジェクトを含めて10件あるとき、11件目を作成すると「プロジェクトは10件まで作成できます。」になる。アーカイブ済みも件数に含まれる（現実装）。
- [ ] LIM-02 全プロジェクトの合計で30件のサイト（初期データの`learn-seo.example`を含む）があるとき、31件目を追加すると「デモのサイトは30件まで作成できます。」になる（低優先）。アーカイブ済みも件数に含まれる（現実装）。ドメインは`s1.example.com`、`s2.example.com`…のように変える。
- [ ] LIM-03 自分で行った探索・調査・CSV出力の合計が50回に達した後、51回目で「デモでの実行は50回までです。ゲストログインし直すと初期化されます。」になる（低優先）。初期データの6ジョブは数えない。「キーワードを探す」を繰り返し押すと早い。ログアウトして再びゲストログインすると、また実行できる。

## 12. 手動では確認しない項目

- ゲストのCookieで`POST /account/password`や未対応の操作を直接送ったときの拒否: `WebGuestLoginTests`と`GuestDemoSessionTests`で検証している。
