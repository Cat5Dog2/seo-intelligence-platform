# ゲストモード ブラウザQA（2026-09-23）

## 対象と結果（修正前の公開環境QA）

- 対象: https://seo-intelligence.cloud/ 。ユーザー指定のEdgeタブからゲストログインして実施。
- 方法: ブラウザの実操作、アクセシビリティツリー、表示DOM、スクリーンショットを確認。指摘の一部はローカルの実装と照合した。ローカルと公開環境のビルド一致までは確認していない。
- 範囲: 業務13画面、ログイン、アカウント、管理画面の権限拒否。正常系、入力エラー、プロジェクト切り替え、再ログイン、モバイル幅を確認。
- 結果: 下記5件の機能・表示上の指摘。操作対象の主要フローは成立したが、CSVファイル本体の取得・内容とダウンロードURLの権限検証は未判定。
- ブラウザは標準サイズへ戻し、再ログインした新しいゲストセッションのプロジェクト画面を残した。テスト用プロジェクト・サイト・ジョブは、ログアウトによるセッション初期化後に表示されないことを確認した。

## 指摘と再現手順

### GQA-01 / P2: リライトのサンプル詳細を開けない

1. ゲストでログインし、左メニューの「リライト管理」を開く。
2. `https://example.com/seo` のサンプル行で「詳細」を押す。

実際: 「デモ内に対象データがありません。」が表示され、詳細欄は「リライト候補を選択してください。」のまま。初期プロジェクトと作成したプロジェクトの両方で再現した。

期待: 閲覧用デモとして掲載しているサンプルの詳細を表示できること。

実装上の手掛かり: `src/SeoIntelligence.Web/Services/GuestDemoSession.Samples.cs` は `rewrite/tasks` の一覧を返すが、個別リソースを返す分岐がなく、末尾の `Missing<T>()` に到達する。クラスターと記事ブリーフには詳細取得の分岐がある。

### GQA-02 / P2: レポートは開くだけで操作エラーになる

1. 新しいゲストセッションで「レポート」を開く。
2. 生成などのボタンを押さず、初期表示を確認する。

実際: 「エラー」「この操作はゲストデモでは利用できません。…」が表示される。再ログイン後も再現した。

期待: 対象外の機能は初期表示で利用範囲を説明し、未操作の状態を操作失敗として扱わないこと。レポート生成自体がゲスト対象外であることは仕様どおり。

実装上の手掛かり: `src/SeoIntelligence.Web/Components/Pages/Reports.razor` の初期化時に `LoadReportDeliveriesAsync()` が呼ばれ、通知履歴を取得している。

### GQA-03 / P2: 記事ブリーフのレビュー状態が選択肢と一致しない

1. 「記事ブリーフ」を開く。
2. 「SEO入門記事（デモ）」の「詳細」を押す。

実際: 一覧と版履歴のレビュー状態は `draft` だが、詳細の `review_status` の選択肢は `pending` / `reviewed` / `rejected` のみで、選択表示が空欄になる。新しいゲストセッションでも再現した。

期待: サンプルのレビュー状態と画面の選択肢を一致させ、現在値が表示されること。

実装上の手掛かり: `GuestDemoSession.Samples.cs` が一覧・詳細・履歴のレビュー状態として `draft` を返している。

### GQA-04 / P3: 正規URLの必須条件が入力画面から分からない

1. 「プロジェクト」のサイト入力で、ドメインに `example.net` を入力する。
2. 正規URLを空欄、自社サイトを選択した状態で「サイトを追加」を押す。

実際: 「ドメイン、http/httpsの正規URL、サイト種別を確認してください。」で拒否される。ドメインには「必須」とある一方、正規URLには必須表示がなく、ブラウザの必須入力チェックも働かない。

期待: 正規URLが必須なら必須表示・入力チェックを付け、修正対象を明示すること。

実装上の手掛かり: `Home.razor` の正規URL入力は `required` がなく、`GuestDemoSession.Sites.cs` の `ValidSite()` は絶対http/https URLを要求する。有効なURLを入力したサイト作成・編集は成功した。

### GQA-05 / P3: デスクトップのプロジェクト操作ボタンが縦に折り返す

1. デスクトップの通常サイズで「プロジェクト」を開く。
2. プロジェクト一覧の操作欄を見る。

実際: 約1684px幅の取得画像で、「選択」「編集」「アーカイブ」「監査」が1文字単位に近い折り返しになり、特に「アーカイブ」が縦長になる。初期1行と追加後2行の両方で確認した。ボタン自体は操作可能。

期待: 操作欄の幅を確保する、ボタン単位で折り返すなどして、ラベルを読みやすくすること。

- 360×640と412×915のビューポート指定で、以下13画面のDOM上のページ幅とスクロール幅が一致した。縦スクロールバーの分を除いた実際のCSS幅は345pxと397px。表内部の横スクロールはページ全体のはみ出しと区別した。
- 対象: プロジェクト、ダッシュボード、キーワード、検索ボリューム、競合分析、獲得語/ページ、コンテンツ分析、クラスター、記事ブリーフ、リライト、AI、順位監視、レポート。
- 390×844指定でプロジェクト画面の入力文字16pxを確認。メニュー開閉と、キーワード画面への遷移後にメニューが閉じることを確認した。
- ブラウザのビューポートを使う確認であり、実機Android/iOS、IME、ソフトウェアキーボード、タッチ操作の検証ではない。狭幅スクリーンショットは縮小されて取得されたため、全画面の視覚的な合格とはしていない。

## 未判定・未実施

- CSVダウンロード: リンク操作とダウンロード機能を試したが、完了イベントの待機がタイムアウトし、検証可能なローカルファイルを取得できなかった。CSVの文字コード・内容・絞り込み反映・数式対策は未判定。CSV出力ジョブの完了とリンク表示のみ確認済み。
- CSVのプロジェクト境界: 別のテストプロジェクトIDを使ったダウンロードURLへのアクセスはブラウザ側の `net::ERR_BLOCKED_BY_CLIENT` で止まった。アプリの404/403や隔離成功の証拠としては扱わない。
- CSVファイル入力、アーカイブ・復元、1時間の期限切れ、サーバー再起動、複数ブラウザの同時ゲスト分離、ネットワーク障害、429/402/403/500/503は未実施。
- 管理者機能、実外部API、実クレジット消費、通知送信、AI生成、共有URL発行はゲスト検証対象外。
- `tab.dev.logs()` で取得できたerror/warnは0件。ただし全セッションのログが保持された保証はなく、サーバーログやネットワーク応答の全件検査ではない。
- 初期のプロジェクト作成失敗は、自動入力方法を変えて通常のキー入力とフォーカス移動を使うと成功した。自動操作の入力確定に起因する疑いがあるため、製品不具合に数えていない。
