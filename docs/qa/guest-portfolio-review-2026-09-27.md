## 再現できた問題・改善優先順位

優先度は面接用デモへの影響で付けた。P2は面接公開前に優先して直したいもの、P3は体験・説明の改善。

### GPR-01 / P2: 追加プロジェクトの結果ページを再読み込みすると結果が開けない

手順:

1. `QA-Portfolio-Edited`を選択する。
2. 検索ボリュームで`Portfolio SEO`を調べ、1件の結果を表示する。
3. ダッシュボードの「結果を開く」から結果ページへ移動する。
4. ブラウザで再読み込みする。

実際: 選択中プロジェクトが「デモプロジェクト」に戻り、「このプロジェクトの検索ボリュームジョブが見つかりません。(jobId)」となる。URLはジョブIDのみを含む。元のプロジェクトを再選択しただけでは結果は0件のまま。ダッシュボードに戻って結果を開き直すと復帰できた。

期待: 再読み込み後も該当プロジェクトの結果を開けるか、どのプロジェクトを選べばよいか案内する。

影響: 面接担当が更新、URLの再訪、別タブでの再表示を行うと「保存した調査が壊れた」と受け取りやすい。

提案: URLと選択プロジェクトの復元を整合させる。プロジェクト境界の検証は維持する。

証跡: [エラー画面](guest-portfolio-2026-09-27/project-result-reload.png)、[画面テキスト](guest-portfolio-2026-09-27/project-result-reload.txt)、[復帰後](guest-portfolio-2026-09-27/result-recovered.png)。

### GPR-02 / P2: 保存したキーワード候補を画面再訪で開けない

手順: `SEO`を探索して「5件の候補語を保存しました」を確認した後、別画面へ移動してキーワード画面へ戻る。

実際: シード欄は空、候補0件、「候補語はありません」。ダッシュボードには完了したキーワード探索履歴が残るが、探索の行には検索ボリュームのような「結果を開く」操作がない。

期待: 最後の探索結果または履歴から保存済み候補を再表示できる。

影響: データが消えたように見え、同じ探索をやり直す必要がある。「保存しました」という文言と再利用の体験がつながらない。DB等からデータが失われたことを確認したわけではない。

提案: 保存済み探索への履歴導線、直近結果の復元、またはセッション中の表示状態の保持を追加する。

証跡: [再訪時](guest-portfolio-2026-09-27/keyword-return-empty.png)、[画面テキスト](guest-portfolio-2026-09-27/keyword-return-empty.txt)、[保存済み探索の履歴](guest-portfolio-2026-09-27/dashboard.txt)。

### GPR-03 / P2: リライトの理由がUnicodeエスケープのJSONで表示される

手順: リライト管理のサンプル行を表示し、「詳細」を押す。

実際: 一覧の理由と詳細の「選定理由（JSON）」に`{"summary":"\u691C\u7D22..."}`のような表記が出る。日本語の理由として読めない。デスクトップでも一覧が狭い欄の横スクロールになり、長いJSONが閲覧を妨げる。

期待: 「検索意図に合わせて見出しを改善」のような理由を普通の日本語で読める。

提案: 一覧・本文にsummaryを表示し、必要なら生JSONを補助的な折りたたみに置く。記事ブリーフの読みやすい本文表示に揃える。

証跡: [リライト画面](guest-portfolio-2026-09-27/rewrite.png)。

### GPR-04 / P2: ゲストの検索ボリューム条件に、結果へ反映されない操作がある

手順: 検索ボリュームの「CSV・調査条件」を開き、集計月数を3、「SEO難易度を取得」を未チェックにし、`SEO test`を調べる。

実際: 調査は成功するが、結果のSEO難易度は30、月別推移は`-`。未チェック状態と難易度30が同時に表示される。

期待: 取得しない条件なら難易度を表示しないか、Mockでは条件によらず固定値であることを入力時に明示する。

判定: ゲストの模擬仕様と操作UIの不整合。実外部APIの障害や本番側の条件処理の不具合とは断定しない。キーワード探索の詳細条件には固定条件の説明がある一方、こちらには同等の説明がない。

提案: 対応しない条件をゲスト時に隠す・無効にする、またはMockの結果にも条件を反映する。

証跡: [入力と結果](guest-portfolio-2026-09-27/ignored-volume-options.png)、[画面テキスト](guest-portfolio-2026-09-27/ignored-volume-options.txt)。

### GPR-05 / P3: 「検索ボリューム調査へ送る」の次の行動が分かりにくい

実際: キーワード候補から実行するとジョブIDの文字列だけが通知され、結果画面へ移動せず、結果へのリンクもない。メニューの検索ボリュームを開くと入力欄と結果0件が表示される。ダッシュボード経由では結果を開ける。

影響: 最も見せたい「発見→需要比較」の途中で操作が途切れる。初見の面接担当にジョブIDや履歴の位置を理解してもらう必要がある。

提案: 「結果を見る」を成功メッセージ内に置くか、その調査結果を自動で表示する。

### GPR-06 / P3: 日本語画面に内部コードが残る

実際: 獲得状況`competitor_only`、クラスターの検索意図`informational`、役割`representative`、リライトの状態選択肢`completed`を確認。一方で他の部分は日本語表示になっている。

提案: 「競合のみ獲得」「情報を知りたい」「代表語」「完了」等へ表示名を統一する。APIの値を変更する必要はない。

## 環境により未判定の項目

### ENV-01: CSVファイル本体のダウンロード

- キーワード候補のCSVは完了100%になった後、ダウンロードを押すとEdgeの「このページはMicrosoft Edgeによってブロックされました」「ERR_BLOCKED_BY_CLIENT」を表示した。
- 検索ボリュームCSVでも生成は完了。ダウンロードの完了をブラウザ操作ツールで待ったが10秒で確認できず、ファイルの保存先は得られなかった。
- ブラウザ・拡張機能・操作環境の影響を切り分けられていないため、アプリ側のCSV障害とは認定しない。
- 既存の手動チェックリストにも過去の同種エラーが記載されている。ただし、今回の原因が同一であることは未確認。
- セキュリティ機能や拡張機能を変更せずに調査を終了した。通常の手動操作または検証用のクリーンなブラウザ環境で、保存・Excel表示・日本語文字化け・フィルター反映を確認する必要がある。

## 面接担当に伝わりにくい点と改善案

1. **入口で全体像が分からない。** ログイン説明はMockの安全性を伝えるが、利用者・課題・成果物・見てほしい機能の説明は少ない。「3分で試す」と、調査→比較→記事構成の案内があると評価しやすい。
2. **高度な機能の体験が薄い。** サンプルが各1件程度で、共起語、記事候補、内部リンク候補、カニバリ候補が空。AIとレポートは実行不可。仕様上の制限として妥当でも、面接担当は実装範囲や完成度を判断しにくい。サンプルを関連付けた1つの事例と、通常ログイン時の完成例を見せたい。
3. **新規プロジェクト作成後の対象が分かりにくい。** 「作成しました。キーワード探索へ進めます」と表示されるが、作成したプロジェクトは自動選択されない。前のプロジェクトのまま調べ始める可能性がある。自動選択か「このプロジェクトで探索」の導線が有効。
4. **サンプルと指標の関係が不明瞭。** 分析画面にはサンプルがある一方、ダッシュボードの分析件数は0。実操作の集計と閲覧用サンプルの区別を補足したい。
5. **成果物を識別しにくい。** 候補語CSVと検索ボリュームCSVが同じ「CSV出力」という履歴名で並ぶ。対象、出力種類、件数などがあると選びやすい。
6. **業務用語の補助が少ない。** CPCの通貨、広告競合性の尺度、機会スコアの読み方などの説明があると、SEO専門外の面接担当にも利用価値が伝わる。

良かった点は、登録不要の入口、Mockであることの明示、日本語の空状態・入力エラー、ブリーフ本文の読みやすさ、モバイルの専用ナビ、完了ジョブから結果を再表示できる点。

面接で見せる順序は、キーワード探索→検索ボリュームの結果・絞り込み→記事ブリーフのサンプル→ダッシュボードが適切。現在は「検索ボリューム調査へ送る」の後にダッシュボードの「結果を開く」を使う必要がある。バックエンドのジョブ設計・分離・監査などは、ブラウザだけでは品質を判断できないため、構成図や実際のテスト内容を別途説明するとよい。

## 未実施・対象外

- プロジェクト／サイトのアーカイブ・復元: ボタンと状態フィルターは確認したが、状態変更は今回の主要導線の調査に含めていない。
- CSVファイルの取込: ファイル選択UIを確認したのみ。ファイル取込とCSV内容の正確性は未検証。
- ログアウト／再ログインによる初期化、1時間の期限切れ、サーバー再起動、最大件数・レート制限: 今回は実行していない。セッションを残して終了した。

- 390px以外のモバイル幅、iPhone Safari／Android Chrome実機、全操作のキーボードのみでの到達性: 未検証。
- Real API・AI生成・通知・共有・Excel/PDF: ゲスト仕様の対象外。
- `dotnet build`、`dotnet test`: 未実行。今回は公開環境のブラウザ調査であり、アプリ実装を変更していない。
